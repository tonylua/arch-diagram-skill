# 流程图风格

视觉参考是[《Skill 路由优化实战》](https://mp.weixin.qq.com/s/K9Eh1zezOx_idgh8bzFvMA)正文里的一组配图（职责分工、回放循环、证据关系、新旧迭代、阶段耗时）。封面那张深色立体插画不是这套风格，不要模仿。

这是流程图，不是分层架构图。不要套用层色带、左侧层名栏、按层循环配色，也不要套用「只留一条居中向下箭头、禁止回头」。

由 `scripts/gen_flow_svg.py` 按本文生成。节点放在哪一行写在 JSON 的 `rows` 里，脚本不做自动排布。

## 一、画面

- 白底。标题是一句结论或动作顺序（如「先分清职责，再修改说明」），居中，深蓝 `#1A237E`，28px 粗体。
- 标题下只放一句副标题，说明这张图该怎么读，蓝色 `#3949AB`，15px。
- 横向展开。步骤从左到右。画布宜宽，避免变成细长的单列。
- 字体 `PingFang SC, Microsoft YaHei, sans-serif`。

## 二、卡片

- 白底、圆角 14、描边 2px。一行里的卡片等高，行在画布上居中。
- 一张卡片只放一个步骤或一个入口：徽章、可选线框图标、一句标题、最多三行说明。
- 卡片里面不再套一套小箭头。循环用外框把节点包起来；分支做成独立节点。
- 徽章是实心圆里的数字或字母，表示顺序或角色，不表示图层。
- 图标只用简单线框，放在文字左侧。没有合适图标就省略，不要画成立体插画。

## 三、颜色表示结果，不表示层

| 颜色 | 用于 |
|---|---|
| 蓝 | 普通步骤、分组外框、中性箭头 |
| 绿 | 通过、交接、成功出口、正向指标 |
| 红 | 失败、拒绝、异常、排除项；回路常用虚线 |
| 橙 | 判断菱形、反馈、需要停下来看的结论 |

不要按节点序号循环蓝橙绿。同一条主链可以全是蓝卡片，只把判断、失败和成功出口换成对应颜色。

## 四、箭头

- 相邻步骤之间画短箭头，标签用颜色写在线上方，例如「通过」「交接」「否」。
- 主链用绿色实线向右。失败、退回、未命中用红色，可以回头，标签写清原因。
- 回头线走节点外侧的底部通道，再从左侧进入目标，不从卡片中间穿过去。
- 判断用橙色菱形，出口至少两条，每条都有标签。
- 没有标签的回头线不要画。跨很多步的关系优先写成页脚里的一句话，而不是再拉一条长线。

## 五、分组：并列入口不是下一步

同一行会从左到右被读成先后。若几张卡片是别的入口、别的能力或别的证据，而不是上一步的后续：

- 放进单独的一行，并加上外框标题，写明「并非上一步的后续」或等价的话。
- 这一行内部默认不连箭头。
- 重复发生的循环用虚线外框，框内才是循环体；离开循环的成功、未命中、异常排在框外。

## 六、页脚和排除条

- 页脚是通栏圆角条，写这张图不能推出的结论，优先用「A ≠ B」。例如「校验通过 ≠ 已经支付」。
- 需要强调「图中的数字或范围不含什么」时，用红色虚线通栏，不要把排除项混进主链卡片。
- 一条红色短句可以单独做提示，用来打断误读（例如某一步可以就此结束）。

## 七、不要画成什么样

- 不要画成分层色带，也不要为了对齐去补不存在的步骤。
- 不要用 Mermaid 自动布局来追求这个版式。
- 不要把封面插画、渐变和立体图标带进来。
- 不要在一张图里同时讲静态分层和完整分支。层次用分层图，分支用本风格。
