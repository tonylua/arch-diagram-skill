# 架构图设计规则与配方

## 一、Mermaid 的已知缺陷（不要在它身上反复微调）

| 现象 | 根因 | 结论 |
|---|---|---|
| subgraph 内写了 `direction LR`，模块仍然竖排 | Mermaid 常忽略 subgraph 内部 direction，尤其当存在跨 subgraph 边时 | 不可修复，换 SVG |
| 图呈「楼梯状 / 斜线错位」 | 跨 subgraph 的边（含 `~~~` 不可见连线）破坏 dagre 聚类布局 | 不可修复，换 SVG |
| 整体细长 | 每层只有 1 个节点，或节点内 `<br/>` 过多把盒子撑高 | 每层铺 3–6 个模块 |
| 宽度参差 | subgraph 宽度由内容撑开，无法强制等宽 | 用脚本固定坐标 |
| 两次渲染结果不一致 | 自动布局对节点数/文本长度敏感 | 用脚本保证确定性 |

经验：**Mermaid 适合「表达方式」，不适合「排版要求」**。一旦用户提出对齐、等宽、别太细长、按层级画这类要求，直接上手写 SVG。

## 二、分层架构图的版面规范（硬性）

1. **层色带必须同宽**：统一 `x = PAD`、`width = band_w`（为右侧场景区预留空间）。
2. **层高与间距一致**：`BAND_H = 100`、`BAND_GAP = 36`；层数 > 6 时必须合并层。
3. **层名左置**：左侧 200px 为层名栏（层名 18px 粗体 + 副标题 11px 灰字），用竖线与模块区分隔。
4. **模块横向铺开并居中**：模块区宽度固定，按模块数均分盒宽（上限 220px，下限 90px），多余留白居中，绝不竖排。
5. **层间单向居中箭头**：只在相邻层之间画，箭头位于画布水平中心；跨层回边一律改成文字说明，不画线。若启用场景卡片，建议关闭箭头（`arrows: false`）。
6. **画布比例**：宽高比控制在 1:1 ~ 2:1 之间；太高说明层数过多或模块太少。
7. **字号层级**：标题 22 / 层名 18 / 副标题 11 / 模块 13（超长自动降到 12、11、10）。
8. **配色与图例**：
   - 层色按顺序循环 `blue → orange → green → purple → teal → grey`
   - 模块默认白底，可自定义 `color` 或用 `highlight: true` 标黄底
   - `legend` 支持单对象或数组，左上角垂直排列
   - 标签含"框"（如"蓝框"）自动渲染为边框样式（白底+彩边），否则为填充样式（彩底+彩边）
   - 示例：`[{"label": "蓝框 = OSS", "color": "blue"}, {"label": "黄底 = 安全", "color": "highlight"}]`
9. **字体**：`font-family="PingFang SC, Microsoft YaHei, sans-serif"`，避免中文渲染成方块。
10. **文本**：模块文字 ≤ 12 字一行，超长拆两行；不做三行以上。
11. **模块数由实际内容决定**：层等宽靠脚本保证（模块在色带内均分居中），**禁止为凑数虚构模块或占位符**；某层模块明显少于其他层是正常且合理的，不要为了"看起来整齐"编造内容。
12. **架构图 ≠ 数据流图**：分层图只表达静态层次与模块归属；调用/数据流向单独出「关键链路图」（`type=flow`），绝不为了画流向而加反向边或跨层边。
13. **场景卡片（可选）**：右侧可添加虚线框卡片展示典型使用场景或数据流示例。每个卡片高度均分全图高度，宽度根据最长内容行自动计算（CJK 字符 ~11px，ASCII ~6px），与层色带间距 30px。适用于：多场景系统、需要展示端到端流程、文档需求。不适用于：单一流程系统、纯组件清单。**询问用户**：在梳理层与模块后，询问是否需要场景卡片展示使用流程。

## 三、用户反馈 → 修正动作对照表

| 用户说 | 真正的问题 | 修正动作 |
|---|---|---|
| 太细长 | 层内竖排 / 每层只有 1 个节点 / 层数过多 | 每层铺 3–6 个横向模块；合并层数；加宽画布 |
| 太乱 | 跨层连线过多、有回边、边交叉 | 只保留相邻层单向边；其余改为说明文字 |
| 缺细节 | 只画了主干流程 | 补充横切措施（校验、兜底、防抖、超时、日志），用 highlight 标出 |
| 没对齐 | 各层宽度随内容变化 | 用 `gen_layered_svg.py` 强制等宽 |
| 认不出重点 | 所有模块一个样式 | 用 highlight 底色区分关键措施，并加图例 |
| 某层模块特别少 | 内容本身如此，属正常 | 不凑数；色带仍等宽、模块自动居中；只有在该层的模块确实可以合并/上提时才调整 |
| 想看数据怎么流 | 架构图不承担流向表达 | 另出关键链路图（`type=flow`） |
| Mermaid 渲染成楼梯 | 跨 subgraph 连线缺陷 | 放弃 Mermaid，改手写 SVG |
| 标题显示错误 | 变量名冲突（场景循环中的 `title` 覆盖主标题）| 场景标题用 `scenario_title`，主标题用 `title`；标题居中基于 `canvas_w/2`，不是层带宽度 |
| 应用层只放了部分任务 | 未筛选真正使用该能力的模块 | 架构图只画使用核心能力的模块；独立支线任务不应出现在知识库架构图中 |
| 黄底高亮莫名其妙 | 使用了 highlight 但未配图例说明含义 | 要么加 `legend` 解释高亮含义，要么移除所有 highlight；支持数组配多个图例 |
| 模块内出现实现细节 | 把配置参数当作架构组件 | 架构图只画逻辑组件和子系统，不画参数值（如"1500字/块"） |
| 层顺序反了 | 误以为需要 reverse 或自作主张调整 | JSON 数组顺序即视觉顺序：第一项在顶部，最后一项在底部，绝不自动反转 |

## 四、其他图型的坐标配方

### 横向流程图（LR 主干）
```
画布宽 = 节点数 * (nodeW + gap) + 2*PAD
节点 y 统一 = 中线；分支用上下偏移 ±60，连线走折线（先横后竖）
```

### 对比图（双栏 / 三栏）
```
列宽 = (canvas_w - 2*PAD - (cols-1)*colGap) / cols
每列：标题条(高 36) + 内容卡(高 = max(行内容))
行高按各列最大文本行数对齐
```

### 时序图（参与者 × 时间轴）
```
参与者表头 y = 80，列宽 = (canvas_w - 2*PAD) / n
消息行 y = 120 + i * ROW_H (ROW_H = 44)
生命线：虚线 x = 列中心，从表头到底部
激活框：宽 12，位于生命线两侧
```

### 网格 / 矩阵图
```
先算列宽 = (canvas_w - 2*PAD - (cols-1)*gap) / cols
行高按内容最大行数 * lineH + padding
表头行底色深一档，斑马纹用 opacity 0.03 的黑块
```

## 五、交付清单

生成后必须确认：
- [ ] 所有层色带宽度一致、左边界对齐
- [ ] 每层模块横向排布、间距均匀、居中
- [ ] 层间箭头居中且单向
- [ ] 无文字溢出盒子（超长已降字号或折行）
- [ ] 高亮块有图例
- [ ] 画布比例在 1:1 ~ 2:1
- [ ] 文件路径已告知用户，并说明用浏览器/IDE 预览打开

## 六、迭代纪律

先与用户确认**层划分**与**每层模块**，再一次性生成，不要逐像素微调。若用户连续两次对排版不满，停止微调当前方案，直接切换到「脚本生成 + 重新梳理层模块」。

## 七、图型分工

| 想表达什么 | 用什么 |
|---|---|
| 静态层次 / 模块归属 | 分层架构图（本 skill 主产物，`type=layered`） |
| 调用链 / 数据流向 / IPC / 消息传递 | 流程图或序列图（参考 UML Activity / Sequence Diagram）|
| 方案对比 / 技术选型 | 决策表或对比视图（参考 Decision Matrix / Comparison View）|
| 时序交互 | Mermaid `sequenceDiagram` |
| 无明确分层的组件关系 | 自由布局 `graph TB` |

分层图只表达"静态层次与模块归属"。其他需求请对照 UML / C4 / ADR（Architecture Decision Records）等既有实践选择图型，不要临时发明或强行套用分层图。

链路图规格示例：

```json
{
  "type": "flow",
  "title": "插件页面加载链路",
  "direction": "LR",
  "nodes": [
    { "text": ["设备接入"], "color": "blue" },
    { "text": ["loadPlugin"], "color": "orange" },
    { "text": ["PluginContainer"], "color": "green" }
  ],
  "edges": [
    { "from": 0, "to": 1, "label": "IPC" },
    { "from": 1, "to": 2, "label": "add-route", "dashed": true }
  ]
}
```

## 八、口诀

**水平靠均分居中，垂直靠层边单向，层次与流向分图，边全向下不回头。**

- **水平**：模块在层内横向均分居中 → 层等宽、不竖排、不细长
- **垂直**：层间单向居中箭头 → 纵向堆叠、不乱
- **分图**：架构图不画数据流，流向另开链路图
- **不回头**：无反向边、无跨层边，跨层依赖一律写成文字说明
- **不凑数**：模块数按实际内容来，等宽由脚本负责，绝不为了对齐编造模块
